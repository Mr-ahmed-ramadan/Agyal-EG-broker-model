# Hosted demo: deployment guide

This puts the platform online as a **demo**: real sign-in codes by email,
simulated banks, mock identity checks, no real money. Share it with brokers
for feedback, not for real clients.

## What you will have

| Part | Where | Address (example) |
| --- | --- | --- |
| Client app (white-label, EN/AR) | Vercel | `https://invest.yourdomain.com` |
| Broker console | Vercel | `https://broker.yourdomain.com` |
| Agyal admin console | Vercel | `https://admin.yourdomain.com` |
| API | Render (web service) | `https://api.yourdomain.com` |
| FIX gateway + 2 simulated banks | Render (background worker) | no public address |
| Database | Render PostgreSQL | private |
| Sign-in/confirmation codes | Resend (email) | from `codes@yourdomain.com` |

Replace `yourdomain.com` with your domain everywhere below.

**Approximate cost** (check current prices): Render PostgreSQL basic plus two
starter services, roughly USD 20/month; Vercel Hobby and Resend's free tier
are enough for a demo. Render's free plans are not suitable: free databases
are deleted after 30 days and free web services sleep.

**Before you start**: Render and Vercel deploy from GitHub. Either merge the
branch `claude/eloquent-einstein-ivn1h6` into `main`, or pick that branch
when you create each service/project below.

## Step 1 — Resend (email for codes)

1. Resend → **Domains** → **Add domain** → `yourdomain.com` (or a subdomain
   such as `mail.yourdomain.com`). Region: EU (Ireland) is closest.
2. Resend shows DNS records (SPF/DKIM `TXT` and an `MX` for bounces). Add
   them at your DNS provider (Step 4), then click **Verify** in Resend.
3. Resend → **API Keys** → **Create API key**, permission "Sending access",
   limited to that domain. Copy it (starts with `re_`). You need it in Step 2.
4. Choose the sender address, e.g. `codes@yourdomain.com`. It doesn't need a
   mailbox; the domain just has to be verified.

## Step 2 — Render (database, API, FIX)

1. Render → **New** → **Blueprint** → connect the GitHub repository
   `Mr-ahmed-ramadan/Agyal-EG-broker-model` → choose the branch.
2. Render reads `render.yaml` and proposes: `agyal-db`, `agyal-api`,
   `agyal-fix`. It asks for these values:

   | Variable | Value |
   | --- | --- |
   | `RESEND_API_KEY` | the `re_...` key from Step 1 |
   | `EMAIL_FROM` | `codes@yourdomain.com` |
   | `CORS_ORIGINS` | `https://invest.yourdomain.com,https://broker.yourdomain.com,https://admin.yourdomain.com` |
   | `ADMIN_EMAIL` | **your** email: you will sign in to the admin console with it |
   | `ADMIN_MOBILE` | your Egyptian mobile, e.g. `01012345678` (stored; codes go by email for now) |
   | `ADMIN_PASSWORD` | a strong password, 12+ characters |

   `JWT_SECRET`, `OTP_SECRET` and `KMS_MASTER_KEY_LOCAL` are generated by
   Render. Don't change them later: `KMS_MASTER_KEY_LOCAL` encrypts stored
   national IDs.
3. Click **Apply**. The first deploy takes several minutes. The API runs
   database migrations and the seed on every start (safe to repeat): it
   creates your admin user, the demo broker "Demo Securities", two simulated
   FIX banks and demo instruments.
4. Check: `agyal-api` → **Logs** shows `Nest application successfully
   started`; `agyal-fix` → **Logs** shows `Logon: FIX.4.4:AGYAL->SIMBANK` and
   `...->SIMBANK2`. If the API log says *"Refusing to start with an unsafe
   production configuration"*, it lists exactly which variable to fix.
5. `agyal-api` → **Settings** → **Custom Domains** → add
   `api.yourdomain.com`. Render shows the DNS record to create (Step 4).

## Step 3 — Vercel (three apps)

Create three projects from the same repository (Vercel → **Add New** →
**Project** → import the repository → pick the branch). For each project:

| Project | Root Directory | Environment variables | Domain |
| --- | --- | --- | --- |
| `agyal-invest` | `apps/client-web` | `VITE_API_URL=https://api.yourdomain.com`, `VITE_TENANT=demo-broker` | `invest.yourdomain.com` |
| `agyal-broker` | `apps/broker-console` | `VITE_API_URL=https://api.yourdomain.com`, `VITE_TENANT=demo-broker` | `broker.yourdomain.com` |
| `agyal-admin` | `apps/admin-console` | `VITE_API_URL=https://api.yourdomain.com` | `admin.yourdomain.com` |

- Framework, install and build commands come from each app's `vercel.json`;
  leave Vercel's defaults.
- Keep **"Include source files outside of the Root Directory"** enabled (the
  apps build the shared types package).
- After adding each domain (**Settings** → **Domains**), Vercel shows the DNS
  record to create (Step 4).
- `VITE_...` values are baked in at build time: after changing one,
  **Redeploy**.

## Step 4 — DNS records (at your domain provider)

| Name | Type | Value |
| --- | --- | --- |
| `invest` | CNAME | as shown by Vercel (usually `cname.vercel-dns.com`) |
| `broker` | CNAME | as shown by Vercel |
| `admin` | CNAME | as shown by Vercel |
| `api` | CNAME | as shown by Render (`agyal-api.onrender.com` or similar) |
| Resend records | TXT / MX | exactly as shown in Resend |

HTTPS certificates are issued automatically once the records resolve
(usually minutes; up to an hour).

## Step 5 — First sign-in and setup

1. Open `https://admin.yourdomain.com`, sign in with `ADMIN_EMAIL` /
   `ADMIN_PASSWORD`, enter the 6-digit code from your email.
2. **Brokers** → *Demo Securities* → **Staff** → add the people who will
   test the broker side, with **real email addresses** (codes go there). Use
   separate people (or email aliases like `you+ops@gmail.com`) for:
   - compliance (approves flagged clients),
   - ops (unified codes, deposits, settlements, coupons, paying withdrawals),
   - finance (approves withdrawals, sweeps revenue; must be a different
     person from the one who pays).
3. Partner banks and instruments are already there. To test a maturity
   quickly: **Instruments** → add a corporate bond maturing in ~2 weeks with
   12 coupons per year.

## Step 6 — Tester's checklist

Share `https://invest.yourdomain.com` and `https://broker.yourdomain.com`.

**Client (phone or browser)**

| Do | Expect |
| --- | --- |
| Open an account with your email and an Egyptian mobile | Code arrives by email; after it, the onboarding wizard |
| Identity: national ID `29001011234567`, your name | Passes (demo check). An ID ending `9999` fails the face match |
| Profile, investment profile, unified code (say you have one: `12345678`), agreements, submit | "Custody account being opened" |
| (Ops approves the code — below) then Portfolio | Your deposit reference (e.g. `AG7K2...`) |
| (Ops posts a deposit) Invest → a T-bill → 25,000 → Get live price | Two bank prices within seconds; your yield, fees and total |
| Buy | Order completes; holding appears |
| Portfolio → Sell part of it | Bank bids; net proceeds; order completes |
| Withdraw | Add IBAN `EG380019000500000000263180002` in your own name; email code; request an amount; email code |
| Switch to العربية | Whole app in Arabic, right-to-left |

**Broker console**

| Role | Do | Expect |
| --- | --- | --- |
| Compliance | Compliance queue | A client whose name contains "Minister Example" or who ticks the PEP box appears here; approve/reject with a note |
| Ops | Unified codes & custody | Enter the code and custody accounts (MCDR and CBE) → client can trade |
| Ops | Deposits | Client's deposit reference, an amount, any bank reference → client's cash updates |
| Ops | Settlements | Confirm each completed trade with any statement reference |
| Ops | Coupons & maturities | Confirm the coupon, then the redemption, of a short bond → client credited, holding closed |
| Finance | Withdrawals → Approve; Ops → Record payment | Same person can't do both |
| Finance | Ledger → Record transfer (revenue sweep) | Trial balance nets to zero |

**Admin console**: Brokers, Instruments, FIX monitor (outbox pending should
stay at 0; "stuck" means the `agyal-fix` worker is down).

## Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| "We could not send your code right now" | Resend key wrong or domain not verified: Render → `agyal-api` → Logs shows the Resend error |
| Browser console: CORS error | `CORS_ORIGINS` doesn't list the app's exact `https://` address; fix and redeploy the API |
| Apps load but every call fails | `VITE_API_URL` wrong in Vercel; fix and redeploy the app |
| "Asking our partner banks for prices…" never ends | `agyal-fix` worker not running; check its logs and the admin FIX monitor |
| "Please wait before requesting another code" | Normal: 30 seconds between codes for the same action, 10 codes per hour per user |

## Security notes for the demo

- Codes go by email, not SMS, until an Egyptian SMS gateway is chosen.
- `DEMO_MODE=true` lets ops confirm coupons/redemptions early. Remove it for
  anything beyond a demo.
- No real money, banks or MCDR are connected; say so to testers.
- When the demo is over, delete the Render services and database.

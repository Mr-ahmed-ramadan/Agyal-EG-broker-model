# Hosted demo on egypt.agyal.net

This puts the platform online as a **demo** for prospect brokers: a landing
page, branded demos per prospect, real sign-in codes by email, simulated
banks, mock identity checks and no real money.

## What you will have

| Address | What | Hosted on |
| --- | --- | --- |
| `https://egypt.agyal.net` | Landing page for brokers (EN/AR), with contact form | Vercel |
| `https://invest.egypt.agyal.net` | Client app (white-label; `?broker=<slug>` picks the brand) | Vercel |
| `https://broker.egypt.agyal.net` | Broker console (same `?broker=<slug>`) | Vercel |
| `https://admin.egypt.agyal.net` | Agyal admin: prospect demos, leads, brokers, instruments, FIX monitor | Vercel |
| `https://api.egypt.agyal.net` | API | Render (web service) |
| — | FIX gateway + 2 simulated banks | Render (background worker) |
| — | Database | Render PostgreSQL |
| — | Sign-in codes and lead emails, from e.g. `codes@agyal.net` | Resend |

**Approximate cost** (check current prices): Render PostgreSQL basic plus two
starter services, roughly USD 20/month; Vercel Hobby and Resend's free tier
are enough for a demo. Render's free plans are not suitable (free databases
are deleted after 30 days; free web services sleep).

**Before you start**: Render and Vercel deploy from the `main` branch on
GitHub; every push to `main` redeploys. Check that `main` is the repository's
default branch (GitHub → **Settings** → **General** → **Default branch**).

## Step 1 — Resend (emails)

`agyal.net` does not need an email service or mailboxes: Resend only needs
DNS records proving you own the domain. Nobody can reply to
`codes@agyal.net`, and the platform never needs replies there.

1. Resend → **Domains** → **Add domain** → `agyal.net` (region Ireland,
   eu-west-1).
2. Resend shows 3–4 DNS records: a TXT at `resend._domainkey` (DKIM), and an
   MX and a TXT at `send` (bounces/SPF). Your DNS is in Vercel: Vercel →
   **Domains** → `agyal.net` → **DNS Records** → add each record:
   - **Name**: only the part Resend shows (`send`, `resend._domainkey`);
     Vercel appends `.agyal.net` itself.
   - **Value**: exactly as Resend shows it; **MX priority** as shown
     (usually 10).

   The records sit on subdomains, so they don't clash with anything else on
   `agyal.net`. Then click **Verify** in Resend (minutes, up to an hour).
3. Resend → **API Keys** → **Create API key** (sending access, `agyal.net`
   only). Copy the `re_...` key.
4. Sender address: `codes@agyal.net` (no mailbox needed).
5. Use your normal inbox (e.g. Gmail) for `CONTACT_TO` and `ADMIN_EMAIL` in
   Step 2. Lead emails set *Reply-To* to the prospect, so **Reply** answers
   them directly.

## Step 2 — Render (database, API, FIX)

1. Render → **New** → **Blueprint** → connect the GitHub repository
   `Mr-ahmed-ramadan/Agyal-EG-broker-model` (branch `main`).
2. Render reads `render.yaml` and proposes `agyal-db`, `agyal-api` and
   `agyal-fix`. It asks for:

   | Variable | Value |
   | --- | --- |
   | `RESEND_API_KEY` | the `re_...` key from Step 1 |
   | `EMAIL_FROM` | `codes@agyal.net` |
   | `CONTACT_TO` | the email(s) that should receive landing-page leads |
   | `ADMIN_EMAIL` | **your** email — you sign in to the admin console with it |
   | `ADMIN_MOBILE` | your Egyptian mobile, e.g. `01012345678` |
   | `ADMIN_PASSWORD` | a strong password, 12+ characters |

   The addresses (`CORS_ORIGINS`, `PUBLIC_CLIENT_URL`, `PUBLIC_BROKER_URL`)
   are already set for `egypt.agyal.net`. `JWT_SECRET`, `OTP_SECRET` and
   `KMS_MASTER_KEY_LOCAL` are generated by Render; don't change them later
   (`KMS_MASTER_KEY_LOCAL` encrypts stored national IDs).
3. **Apply**. The first deploy takes several minutes. If `agyal-api` fails
   with `P1001: Can't reach database server`, it started before the new
   database was ready: wait until `agyal-db` is **Available**, then
   `agyal-api` → **Manual Deploy** → **Deploy latest commit** (same for
   `agyal-fix`). On every start the API
   runs migrations and the seed (safe to repeat): your admin user, the demo
   broker "Demo Securities" (used as the template for prospect demos), two
   simulated FIX banks and demo instruments.
4. Check the logs: `agyal-api` shows `Nest application successfully
   started`; `agyal-fix` shows `Logon: FIX.4.4:AGYAL->SIMBANK` and
   `...->SIMBANK2`. If the API says *"Refusing to start with an unsafe
   production configuration"*, it lists exactly what to fix.
5. `agyal-api` → **Settings** → **Custom Domains** → add
   `api.egypt.agyal.net`. Note the target it shows (e.g.
   `agyal-api.onrender.com`) for Step 4.

## Step 3 — Vercel (four projects)

Vercel → **Add New** → **Project** → import the same repository four times
(production branch `main`):

| Project | Root Directory | Environment variables | Domain |
| --- | --- | --- | --- |
| `agyal-showcase` | `apps/showcase` | `VITE_API_URL=https://api.egypt.agyal.net` | `egypt.agyal.net` |
| `agyal-invest` | `apps/client-web` | `VITE_API_URL=https://api.egypt.agyal.net`, `VITE_TENANT=demo-broker` | `invest.egypt.agyal.net` |
| `agyal-broker` | `apps/broker-console` | `VITE_API_URL=https://api.egypt.agyal.net`, `VITE_TENANT=demo-broker` | `broker.egypt.agyal.net` |
| `agyal-admin` | `apps/admin-console` | `VITE_API_URL=https://api.egypt.agyal.net` | `admin.egypt.agyal.net` |

- **Root Directory is essential**: without it Vercel builds the whole
  repository (including the API) and detects the wrong framework. In an
  existing project it is under **Settings → Build and Deployment**, a plain
  text field. Framework preset: **Vite**.
- Leave build settings on Vercel's defaults; each app's `vercel.json`
  supplies them. Keep **"Include source files outside of the Root
  Directory"** enabled.
- `VITE_TENANT=demo-broker` is only the default brand; a prospect link
  (`?broker=<slug>`) overrides it.
- Domains: project → **Settings** → **Domains** → add the domain. If it
  shows *Invalid Configuration*, add the CNAME it recommends (e.g.
  `egypt` / `invest.egypt` / `broker.egypt` / `admin.egypt` →
  `xxxxxxxx.vercel-dns-017.com`) under Vercel → **Domains** → `agyal.net`
  → **DNS Records**.
- Open the apps only on their `egypt.agyal.net` addresses: the API refuses
  other origins (e.g. `*.vercel.app`), which shows as "Can't reach the
  server".
- `VITE_...` values are baked in at build time: after changing one,
  **Redeploy**.

## Step 4 — DNS for the API (in Vercel)

Vercel → **Domains** → `agyal.net` → **DNS Records** → add:

| Name | Type | Value |
| --- | --- | --- |
| `api.egypt` | CNAME | the Render target from Step 2.5 (e.g. `agyal-api.onrender.com`) |

The four web addresses are handled by Vercel automatically (Step 3). HTTPS
certificates appear once records resolve (minutes; up to an hour).

## Step 5 — First sign-in

1. Open `https://admin.egypt.agyal.net`, sign in with `ADMIN_EMAIL` /
   `ADMIN_PASSWORD` and the code from your email.
2. Open `https://egypt.agyal.net`, send yourself a message through the
   contact form, and check it arrives by email and under **Leads**.

## How to showcase to a prospect broker

**Before the meeting (2 minutes)**
1. Admin console → **Prospect demos**.
2. Firm name in English and Arabic, upload their logo (from their website),
   pick their brand colour.
3. Optionally enter the prospect's email and mobile to give them their own
   broker-console login (a temporary password is shown once).
4. **Create demo** → copy the two links.

**In a 10-minute call (screen-share or on their phone)**
1. Open the client link on a phone: their name and logo, in Arabic and
   English (switch language).
2. Open an account: identity (national ID `29001011234567`), profile,
   investment profile, unified code (`12345678`), agreements.
3. In the broker console (their brand): **Unified codes & custody** → enter
   the code with an MCDR and a CBE custody account; **Deposits** → post a
   deposit to the client's reference.
4. Back on the phone: **Invest** → a T-bill → **Get live price** → two bank
   prices arrive over FIX → **Buy** → completed in seconds.
5. Show **Sell** before maturity, **Withdraw** to an IBAN
   (`EG380019000500000000263180002`, in the client's own name), and in the
   console **Orders**, **Settlements**, **Coupons & maturities** and the
   **Ledger**.
6. Close with the landing page's pricing and "you stay the licensed party".

**After the call**: send them the client link to play with; follow up from
the **Leads** list.

## Tester's checklist

| Where | Do | Expect |
| --- | --- | --- |
| Landing page | Open on a phone; switch to العربية; submit the form | Readable, right-to-left in Arabic; "Thank you"; lead emailed and listed in admin |
| Client app | Open an account with your email and a mobile | Code by email; onboarding wizard |
| Client app | National ID ending `9999` | Identity check fails (demo rule) |
| Client app | Name containing "Minister Example" or tick PEP | Goes to the broker's compliance queue |
| Broker console | Compliance, Unified codes, Deposits, Settlements, Coupons, Withdrawals, Ledger | As in the walkthrough; the person who approves a withdrawal can't also record its payment |
| Admin console | FIX monitor | Outbox pending stays at 0 ("stuck" means the `agyal-fix` worker is down) |

## Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| "Can't reach the server at https://api.egypt.agyal.net" | `/health` fails → API down or its domain not verified on Render. `/health` works → the page's address isn't in `CORS_ORIGINS`; `agyal-api` logs show `Refused origin …` |
| "We could not send your code right now" | Resend key wrong or `agyal.net` not verified: see `agyal-api` logs |
| Contact form works but no email arrives | `CONTACT_TO` not set or Resend not verified; the lead is still under **Leads** with the error |
| Browser console: CORS error | The page's exact `https://` address is missing from `CORS_ORIGINS` on `agyal-api` |
| Apps load but every call fails | `VITE_API_URL` wrong in that Vercel project; fix and redeploy |
| Prospect link shows "Demo Securities" | The link lost its `?broker=...` part; copy it again from **Prospect demos** |
| "Asking our partner banks for prices…" never ends | `agyal-fix` worker not running; check its logs and the FIX monitor |
| "Please wait before requesting another code" | Normal: 30 seconds between codes for the same action, 10 per hour per user |

## Security notes for the demo

- Codes go by email until an Egyptian SMS gateway is chosen.
- `DEMO_MODE=true` lets ops confirm coupons/redemptions early; remove it for
  anything beyond a demo.
- No real money, banks or MCDR are connected; say so to prospects.
- Prospect demos share the demo database; don't put real client data in them.
